# dbpull

新しいターミナルで `dbpull` を実行します。現在開いているターミナルでは一度 `source ~/.zshrc` を実行してください。プロジェクト直下の `./dbpull` でも動作します。

- `dbpull --check`: 本番・ローカルの接続と mysqldump の存在を確認。DBの書き換えやエクスポートは行いません。
- `dbpull`: 対象を表示し、`yes` の入力後、本番を取得 → ローカルをバックアップ → 取り込み。

SSH接続先は www178.conoha.ne.jp:8022、本番アプリは `/home/c1248652/laravel/dqx_laravel` です。接続設定はそれぞれのLaravel設定から取得し、パスワードを引数・ログに出しません。SSH先へスクリプトはインストールしません。

## 取り込み範囲と注意

本番に存在するテーブルの構造とデータを置き換えます。本番にないローカル専用テーブルは削除しません。ビュー・トリガーは mysqldump の標準範囲に含まれますが、ストアドルーチン・イベント・MySQLユーザーは対象外です。`.env` と画像などのファイルは変更しません。マイグレーションも自動では実行しません。

実行前にローカルのアプリ・キューワーカーを停止してください。ジョブやセッションなども本番データに置き換わります。メールなど外部サービスのローカル設定を確認してからアプリを再開してください。

`APP_ENV=local`、MySQL、ローカルホストへの単一接続が必須です。既知のSSHホスト鍵を要求します。本番では読み取りのみ行います。エクスポート中の本番DDL変更は避けてください。`--single-transaction` の整合性保証はInnoDBが対象です。

## バックアップと失敗時

`storage/app/private/dbpull/local_日時_識別子.sql` にバックアップを保存します。この場所はGit管理対象外で、ファイルは所有者だけが読み書きできます。バックアップは自動削除しないため、不要な古いものは手動で削除してください。

取得・バックアップが失敗したら取り込みません。MySQLのDDLはトランザクションで元に戻せないため、取り込み途中の失敗では一部が更新済みになる場合があります。その場合は表示されたバックアップを、ローカル用MySQL接続でインポートして復元してください。復元もテーブル単位の置き換えであり、追加されたテーブルは自動削除されません。失敗中に生成されたバックアップは不完全な可能性があるため、完了したバックアップのみ利用してください。
